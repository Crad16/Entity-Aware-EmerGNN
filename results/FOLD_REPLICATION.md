## 읽는 법

- **세 분할.**
  - S1은 원 논문의 emerging drug 설정입니다. 테스트 쌍마다 학습에서 본 적 없는 새 약이 하나씩 들어 있습니다.
  - S1_12와 S1_123은 원 논문이 공개한 다른 분할입니다. 새 약은 분할마다 160여 개이고, 그중 S1_1과 겹치는 것은 21~24개뿐입니다.
  - 그래서 "다른 새 약들에서도 같은 결론이 나오는가"를 보는 시험이 됩니다.
- **모델.**
  - 분할마다 baseline(게이트 없음, 원 EmerGNN 구조), llm, name 세 모델을 학습했습니다.
  - 설정은 같습니다: 20 epoch, seed 0, shuffle, 2 epoch마다 평가.
  - 분석에는 검증 F1이 가장 높은 epoch의 체크포인트(best)를 씁니다.
  - S1_1의 llm·name은 팀이 올린 체크포인트입니다. S1_1 baseline은 이 서버에서 같은 코드로 다시 학습한 것입니다(아래 주의할 점 참고).
- **표본.**
  - 2장·3장은 원 보고서와 같은 규칙(타입별 층화, `RandomState(0)`)으로 뽑은 테스트 표본에서 쟀습니다.
  - 표본은 S1_1 8,195쌍 / S1_12 8,200쌍 / S1_123 8,191쌍입니다. 새 약은 157 / 152 / 151개입니다.
  - 1장과 4장은 테스트 전체를 씁니다.
- **신뢰구간.**
  - 표기는 `평균 [2.5%, 97.5%]`입니다. 새 약 단위로 bootstrap 했습니다.
  - `*`는 신뢰구간이 0을 포함하지 않는다는 뜻입니다. AUC는 기준을 0.5로 봅니다.
- **dlogp.**
  - 정답 타입의 log 확률이 조작 전후로 얼마나 변했는지입니다(조작 후 − 조작 전).
  - 음수면 모델이 정답을 덜 믿게 됐다는 뜻입니다.
- **분할 난이도.**
  - 분할마다 난이도가 다릅니다. S1_123 정확도가 S1_1보다 약 0.08 높습니다.
  - 그래서 절대값보다 **방향과 유의성이 같은가**를 봅니다.
- **재현 확인.**
  - 팀 코드를 이 서버에서 다시 돌려 S1_1 커밋 결과와 비교했습니다. 다음 항목은 모두 같게 나왔습니다.

## 0장. 출발점: 성능

**무엇을 묻나.** 게이트를 붙이면 성능이 오르는가?

**어떻게 쟀나.**

- 아래 표에는 검증 최적 epoch과 그때의 테스트 정확도도 함께 적었습니다.

| 항목 | S1_1 | S1_12 | S1_123 |

| llm F1 | 0.610 | 0.618 | 0.634 |

- 다른 팀원이 돌리는 추가 seed가 나오면 이 ±0.01이 잡음인지 확정됩니다.

## 1장. 원 EmerGNN은 엔티티를 고를 수 없다 (M2)

**무엇을 묻나.**
- EmerGNN은 엣지에 relation 종류별 가중치만 줍니다.
- 그래서 "약A → CYP3A4 → 약B"와 "약A → CYP2D6 → 약B"는 relation 순서가 같아(결합 → 결합⁻¹) 메시지가 똑같습니다.
- 모델은 어느 CYP를 거쳤는지 구별할 방법이 없습니다. 이렇게 순서가 같은 경로를 "동점"이라고 부릅니다.
- 이 장은 KG와 모델 구조만 보고 센 것이라 학습된 가중치와 무관합니다.

**어떻게 쟀나.** 테스트 쌍 전부에 대해, 약물이 아닌 엔티티를 거치는 2-hop / 3-hop 경로를 셌습니다. 지표는 원 보고서와 같습니다.
- **동점 비율:** 다른 경로와 relation 순서가 같은 경로의 비율입니다.
- **동점 크기:** 경로 하나를 골랐을 때 순서가 같은 경로의 수입니다.
- **집어낼 확률:** 경로 기반 설명이 특정 엔티티를 정확히 가리킬 확률(1/동점 크기)입니다.

| 항목 | S1_1 | S1_12 | S1_123 |
|---|---|---|---|
| 테스트 쌍 | 32,322 | 30,731 | 32,845 |
| 2-hop 경로가 있는 쌍 | 22,953 | 21,196 | 22,228 |
| 2-hop 동점 비율 (전체) | 0.889 | 0.886 | 0.875 |
| 2-hop 동점 비율 (대사형) | 0.908 | 0.889 | 0.868 |
| 2-hop 동점 비율 (비PK) | 0.893 | 0.889 | 0.871 |
| 2-hop 동점 크기 중앙값 | 23.1 | 20.9 | 23.0 |
| 2-hop 집어낼 확률 | 0.170 | 0.186 | 0.192 |
| 3-hop 동점 비율 | 0.693 | 0.685 | 0.707 |
| 3-hop 집어낼 확률 | 0.385 | 0.394 | 0.374 |
| 대사형 중 결합 유전자를 공유하는 쌍 | 0.827 | 0.829 | 0.823 |
| 대사형 중 CYP를 공유하는 쌍 | 0.825 | 0.826 | 0.818 |
| 비PK 중 CYP를 공유하는 쌍 | 0.233 | 0.223 | 0.207 |
| 동점 유전자 중 CYP 비율 (대사형) | 0.902 | 0.902 | 0.894 |
| 특정 CYP를 집어낼 확률 (대사형) | 0.531 | 0.523 | 0.528 |

**해석.**
- 세 분할의 숫자가 거의 같습니다. 2-hop 경로의 88~89%가 동점이고, 경로 설명으로 특정 엔티티를 집어낼 확률은 0.17~0.19입니다.
- 대사형 쌍의 82%가 CYP를 공유하고, 공유 유전자 동점의 90%가 CYP입니다.
- 그래서 원 EmerGNN은 "CYP 쪽이라는 것은 대체로 가리키지만, 어느 CYP인지는 반반(0.52~0.53)"입니다.
- 이것은 KG와 구조에서 나오는 성질이라 분할이 바뀌어도 그대로입니다.

**판정: ✅ 세 분할 모두 성립.**

## 2장. 그 결과: 공유 CYP가 무딘 "대사형" 신호가 된다 (S1, F4, M1)

**이번에 새로 더한 것.**
- 원 보고서의 2장은 "게이트 끈 모델"(게이트 모델에서 게이트를 모두 1로 고정)로 원 EmerGNN을 대신했습니다.
- 이번에는 분할마다 **게이트 없는 baseline을 따로 학습해서** F4·M1·쏠림을 직접 쟀습니다.
- 그래서 "원 EmerGNN 구조도 이렇다"를 추정이 아니라 측정으로 말할 수 있습니다.

**분류 기준 (원 보고서와 같음).**
- **기전 분류:** 86개 DDI 타입을 대사(2개) / 기타 PK(12) / PD(71) / 불특정(1)으로 나눴습니다. 세 분할 모두 같은 분류표를 씁니다(`ddi_type_classes.tsv`, 타입→분류 동일).
- **매개체:** 두 약이 함께 결합하는 유전자에 CYP가 있음 / 비CYP 유전자만 있음 / 공유 없음입니다.
- **KG 양:** 새 약의 KG 연결 수를 3분위로 나눴습니다.

## 3장. 게이트는 그 자리에서만 엔티티 정보를 쓴다 (F1 + F2)

**무엇을 묻나.** 게이트의 입력은 둘입니다.
- **query:** 지금 어떤 약물 쌍인가.
- **key:** 이 엔티티가 누구인가.

게이트가 실제로 어느 쪽에 반응하는지 보려고, 학습된 모델은 그대로 두고 입력만 바꿔 추론했습니다.

| 조건 | 바꾸는 것 |
|---|---|
| original | 없음 |
| off | 모든 게이트 = 1 (원 EmerGNN과 같은 계산) |

| shuffle_all | query를 테스트 전체의 다른 쌍 것으로 교체 (3회) |
| shuffle_type | query를 같은 타입의 다른 쌍 것으로 교체 (3회) |
| key_perm | key를 같은 종류 엔티티끼리 섞음, 유전자↔유전자 등 (3회) |

## 4장. 게이트는 공유 CYP를 짚는가 (E2, E4)

**무엇을 묻나.**
- 원 EmerGNN은 1장에서 본 대로 공유 유전자들이 모두 동점이라 어느 것이 CYP인지 짚을 수 없습니다.
- 게이트 모델은 엔티티마다 게이트 값이 달라서, 원리상 CYP를 더 높게 매길 수 있습니다.
- 실제로 그렇게 하는지, 그리고 그것이 단지 "연결이 많은 노드"를 고르는 것인지를 봅니다.

**어떻게 쟀나 (E2).**
- **후보와 정답:** 두 약이 함께 결합하는 유전자가 후보이고, 그중 CYP가 정답입니다. CYP와 비CYP 후보가 모두 있는 쌍만 썼습니다.
  - 대사형: 1,630 / 1,371 / 1,442쌍
  - 비PK: 1,426 / 1,658 / 1,672쌍
- **AUC:** 쌍 안에서 CYP를 비CYP보다 높게 매길 확률입니다. 0.5가 무작위입니다.
- **차이:** 대사형 AUC − 비PK AUC입니다. 양수면 대사형 쌍에서만 CYP를 짚는다는 뜻입니다.
- **연결 수가 불리한 AUC:** 비CYP가 CYP 이상으로 많은 약에 결합하는 비교만 모은 것입니다. 연결 수 순으로는 절대 맞힐 수 없는 경우입니다.
  - 대사형: 861 / 686 / 669쌍
  - 비PK: 414 / 452 / 444쌍

    - llm: S1_1, S1_123

  - **S1_12의 llm은 반대로** CYP를 비CYP보다 낮게 매깁니다(0.429*). 연결 수 통제 후에도 CYP 게이트가 내려갑니다(−0.057*).

- **연결 수가 불리한 경우:**
  - S1_12 name(0.723*)과 S1_123 llm(0.598*)은 연결 수로는 절대 맞힐 수 없는 비교에서도 0.5를 넘깁니다.
  - S1_12 llm은 0.381*로 반대입니다.
  - 원 보고서의 "두 모델 모두 0.5를 포함한다"는 S1_1에서만 맞습니다. 다른 분할에서는 넘기기도 하고 반대로 가기도 합니다.

**판정.**
- ✅ 게이트는 허브를 따르지 않습니다.
- 🟡 "게이트가 공유 CYP를 짚는다"는 안정적이지 않습니다. 짚는 방향이 분할(또는 seed)에 따라 바뀝니다.
- 4장 결론은 "게이트는 원 EmerGNN이 구조상 할 수 없는, 엔티티별로 다른 순위를 만든다. 그러나 그 순위가 공유 CYP를 일관되게 위로 올리지는 않는다" 정도로 낮추는 것이 맞습니다.

## 종합: 고쳐 쓴 결론

**모티베이션은 그대로 "KG가 빈약할 때"가 아니라 "KG가 풍부하지만 모호할 때"입니다.** 1장, 2-2, 2-6이 세 분할 모두에서 이를 지지합니다.

1. **원 EmerGNN은 엔티티를 구별하지 못합니다(1장).** 세 분할에서 숫자까지 거의 같습니다.
2. **그 결과 공유 CYP가 무딘 "대사형" 신호가 됩니다(2장).**
   - 세 분할 모두, **게이트 없는 baseline에서도** 확인했습니다.
   - CYP 엣지 0.16%를 지우면 대사형 예측이 무너지고 PD·기타 PK는 좋아집니다.
   - 공유 이웃이 많을수록 과신합니다.
3. **게이트는 그 자리에서 엔티티 정보를 쓰지만 예측을 바꾸지는 못합니다(3장).**
   - key를 섞으면 "대사 & CYP 공유" 쌍이 나빠집니다. name은 3/3, llm은 off 대비 3/3입니다.
   - 정확도는 어느 분할에서도 ±0.01 안입니다.
4. **게이트는 허브를 따르지 않습니다(4장). 그러나 공유 CYP를 일관되게 짚지는 않습니다.**
   - 원 보고서의 "게이트는 공유 CYP를 짚는다"는 S1_1 결과입니다.
   - 다른 분할에서는 key마다 한 번씩 반대로 갑니다.
5. **llm과 name의 성격 차이는 분할마다 뒤바뀝니다(5장).**
   - "llm은 CYP를 부류째 다룬다"는 철회합니다.
   - 일관된 것은 "성능 차이 없음"과 "KG 삭제에 llm이 같거나 더 약함"뿐입니다.

**말할 수 없는 것 (갱신)**

- 게이트가 성능을 올린다는 것: 여전히 말할 수 없습니다(0장, 3장, 세 분할).
- 게이트가 CYP 의존이나 쏠림을 바꾼다는 것: 여전히 말할 수 없습니다. baseline도 똑같이 쏠리고, F4 크기 순서가 분할마다 다릅니다.
- 게이트나 LLM 설명이 KG 빈약을 견디게 한다는 것: 여전히 말할 수 없습니다. 오히려 llm이 같거나 더 약합니다.
- llm에서 보인 효과가 LLM 설명의 의미 때문이라는 것: 여전히 말할 수 없습니다. 팀원이 돌리는 F5(permuted-key 재학습)와 F6(이름 뺀 설명)이 답할 질문입니다.
- 게이트가 공유 CYP를 짚는다는 것: **새로 이 목록에 넣습니다.** 분할마다 방향이 바뀝니다.
- ~~원 EmerGNN이 CYP 경로에 의존한다는 것~~: **이제 말할 수 있습니다.** 분할마다 원 구조 baseline을 학습해 세 분할 모두에서 확인했습니다(분할당 seed 1개).

## 주의할 점

1. **seed가 분할마다 하나입니다.**
   - 4장·5장처럼 분할마다 뒤바뀌는 결과는 분할 차이일 수도, seed 차이일 수도 있습니다.
   - 팀원이 돌리는 S1_1 추가 seed(baseline/llm/name × 2)에 `gate_degree.py`를 돌려 보면 가를 수 있습니다.
   - S1_1 안에서도 seed마다 E2 AUC가 뒤바뀌면, 4·5장의 CYP 짚기 주장은 seed 잡음입니다.
2. **S1_1 baseline이 두 개입니다.**
   - 0장의 S1_1 baseline 행은 원 보고서의 학습 곡선(`results/curves/drugbank_S1_1_emergnn.csv`, 최적 epoch 6)입니다.
   - 2장 F4·M1·쏠림의 S1_1 baseline은 이 서버에서 같은 코드·설정으로 다시 학습한 체크포인트입니다(최적 epoch 14, 표본 정확도 0.714). 팀 저장소에 S1_1 baseline 체크포인트가 없어서 이것을 썼습니다. `DrugBank/saved_models/S1_1_learned_shuf_seed0_best.pt`로 함께 올립니다.
3. **S1_1 층별 표(2-2)는 llm·name 두 모델 평균입니다.**
   - 원 보고서 2-2와 같은 방식입니다(`results/S1_1/stratify_llm_name.json`).
   - 커밋된 `results/S1_1/stratify.json`은 id·random까지 네 모델 평균이라 숫자가 조금 다릅니다.
   - S1_12·S1_123도 llm·name 두 모델로 계산했습니다.
4. **S1_1 KG 삭제 결과 파일.**
   - `results/S1_1/kg_ablation_llm_name_baseline.json`은 llm·name에 baseline을 더해 다시 요약한 것입니다. llm·name 숫자는 커밋된 `kg_ablation.json`과 6.2e-6 이내로 같습니다(2,064개 비교).
   - "게이트 끈 대리 모델" 평균(`emergnn_x4/off`)만 다릅니다. 커밋본은 네 모델, 새 파일은 두 모델 평균이기 때문입니다. 이 값은 이 보고서에서 쓰지 않습니다.
5. **표본과 테스트 전체.**
   - 2장·3장은 표본(약 8,200쌍), 1장·4장은 테스트 전체입니다. 원 보고서와 같습니다.
   - 0장의 최적 epoch 정확도는 테스트 전체, 2-4의 "정확도 전체 KG"는 표본 값이라 조금 다릅니다.
6. **학습 환경.**
   - S1_12·S1_123 모델 6개는 이 서버에서 학습했습니다. S1_12 baseline은 PRO6000(7.4시간), 나머지 5개는 A5000(11시간 안팎)입니다.
   - 학습 코드와 하이퍼파라미터는 팀 저장소와 같습니다.

## 재현 방법

`DrugBank/`에서 실행합니다. `S1_12` 자리에 분할 이름을 넣으면 됩니다. 순서는 실제로 돌린 순서와 같습니다. GPU 단계는 하나에 10~45분, CPU 단계는 합쳐 1분 남짓 걸렸습니다.

```bash
# GPU: 게이트 개입 (3장)
python ../analysis/gate_interventions.py --dataset S1_12 --keys llm name --ckpt saved_models/S1_12_learned_shuf_gate-llm-v2_seed0_best.pt saved_models/S1_12_learned_shuf_gate-name-v2_seed0_best.pt
# GPU: KG 삭제 (2장 F4·M1) — 모델마다 한 번, baseline은 full 변형을 더함
python ../analysis/kg_ablation.py --dataset S1_12 --keys llm name --variants cyp hub rand0 rand1 new50 new90 new100 --ckpt saved_models/S1_12_learned_shuf_gate-llm-v2_seed0_best.pt
python ../analysis/kg_ablation.py --dataset S1_12 --keys llm name --variants cyp hub rand0 rand1 new50 new90 new100 --ckpt saved_models/S1_12_learned_shuf_gate-name-v2_seed0_best.pt
python ../analysis/kg_ablation.py --dataset S1_12 --keys llm name --variants full cyp hub rand0 rand1 new50 new90 new100 --ckpt saved_models/S1_12_learned_shuf_seed0_best.pt
# CPU: 나머지 분석
python ../analysis/relation_ties.py --dataset S1_12
python ../analysis/analyze_interventions.py --dataset S1_12 --keys llm name
python ../analysis/stratify.py --dataset S1_12 --keys llm name
python ../analysis/kg_calibration.py --dataset S1_12 --keys llm name
python ../analysis/kg_variants.py --dataset S1_12
python ../analysis/analyze_kg_ablation.py --dataset S1_12 --keys llm name
python ../analysis/gate_degree.py --dataset S1_12 --keys llm name --ckpts best
# 세 분할 비교표 (저장소 루트에서)
python analysis/fold_summary.py --splits S1_1 S1_12 S1_123
```
